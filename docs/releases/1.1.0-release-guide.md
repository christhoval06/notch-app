## Included in this release

- Apple Watch abstinence timer, current level/XP, and monthly stats.
- Swipeable Watch pages, configured and reordered from iPhone Settings → Apple Watch.
- Optional monthly orgasm-count card.
- Watch entries with partner, rating, protection, orgasm count, mood, and tags.
- Offline entry queue with confirmation after the unlocked iPhone saves each entry.
- App Clip preview using fictional entries and the main app's calendar and cards.
- “Get Notch” opens the existing App Store listing.
- Updated iPhone abstinence card and fewer repeated screen titles.

Watch cards are pages inside the Watch app. This release does not include
Smart Stack widgets or watch-face complications.

## App Clip experience

After the uploaded build finishes processing, select it in the new iOS version
and configure the **App Clip** section in App Store Connect.

| Field | Draft content or requirement |
|---|---|
| Header image | Prepare a 1800 × 1200 PNG or JPEG, with a 3:2 aspect ratio |
| English subtitle | Try Notch's private journal with fictional entries. |
| Spanish subtitle | Prueba el diario de Notch con registros ficticios. |
| Action | Choose the available action that fits viewing the preview |
| Default link | Copy the actual generated link from App Store Connect |
| Demo URL | Copy the generated demo URL if using a demo experience |

The Clip uses sample data and does not save journal entries. Its “Get Notch”
button opens `https://apps.apple.com/us/app/notch/id6759076734`.

The earlier unsigned arm64 Clip measured approximately **32 MB**. Check the
actual distribution size and invocation eligibility during archive validation.
For physical QR/NFC demonstrations of a larger Clip, review Apple's generated
App Clip demo URL option. Do not assume every invocation method has the same
size allowance.

Default and demo links become usable after the app and experience are approved
and available. A custom website experience additionally requires domain
association; the generated default link avoids that website setup.

## Signing and archive

1. Confirm all three identifiers belong to the same Apple Developer team.
2. Register the Clip identifier as an App Clip associated with the existing
   Notch iOS parent. Confirm the Watch identifier and refresh provisioning.
3. Open `ios/Runner.xcworkspace`. Check **Signing & Capabilities** for Runner,
   NotchWatch, and NotchClip. Resolve signing errors before archiving.
4. Set the chosen version/build in `pubspec.yaml`, for example `1.1.0+9` only
   after confirming those values are available.
5. From the repository root, run:

   ```sh
   flutter pub get
   flutter build ios --release --config-only
   ```

6. In Xcode, select **Runner → Any iOS Device**, then **Product → Archive**.
7. In Organizer, inspect the archive for both `Watch/NotchWatch.app` and
   `AppClips/NotchClip.app` inside Runner. Confirm matching version/build values.
8. Choose **Validate App**, resolve validation errors, then
   **Distribute App → App Store Connect → Upload**.

## Submit the update

1. In **App Store Connect → Apps → Notch**, create the new iOS version and
   select the processed build with the matching version.
2. Paste the English and Spanish release notes, upload Watch screenshots, and
   complete the default App Clip experience.
3. Add reviewer instructions and complete any fields App Store Connect marks
   as required for this submission.
4. Add the version for review and submit. Select manual or automatic release
   according to the intended launch date.
5. After approval and availability, verify the live listing and generated Clip
   links from a physical device.
